## 1. 变更详述

### 1.1 落地页视觉升级方向（G1）

**目标**：从「扁平直角企业风」升级为「现代 SaaS 多彩质感」，功能零改动（仍为免密出库登记表单，复用 Views.out）。

升级要点：
- **页面背景**：柔和多彩渐变背景（浅紫→浅粉→浅青 的柔和 mesh/渐变），替代纯 `#f4f7fc`；可用 `background: linear-gradient(160deg, #eef2ff, #fdf2f8, #f0fdf4)` 或叠加径向光斑（装饰性 blob，纯 CSS，不加图片资源）。
- **顶栏**：渐变彩条（彩虹细条或主色渐变），品牌标题使用渐变文字（`background-clip: text`）+ 小图标点缀。
- **登记表单卡片**：白卡 + 柔和阴影 + 顶部彩色描边/渐变 accent bar；圆角提升到 10–14px；输入框聚焦时彩色 glow。
- **提交按钮**：主色渐变（靛蓝→紫）胶囊按钮，hover 提亮、active 微下沉。
- **标题/标签**：模块标题、区块标签使用多彩配色（青/玫/橙各司其职），保持可读性（正文仍深灰）。
- **移动端**：单列布局、大点击区不变，仅视觉换肤。

### 1.2 「管理」按钮卡通化（G2）

**位置**：落地页顶栏右侧（landing.js `landingAdmin`）。
**设计规范**：
- 形态：圆角胶囊（`border-radius: 999px`），不再是直角小按钮。
- 配色：彩虹/暖色渐变（如 玫红→橙→琥珀 或 靛蓝→紫），白字 + 柔和阴影。
- 内容：emoji 图标（如 🖥️ / 🛠️ / 🔑）+ 文字「管理」，可加小箭头。
- 动效：hover 轻微放大/弹跳（`transform: scale(1.06)` + emoji wiggle），active 微缩。
- 交互逻辑不变：未登录 → 弹登录框，登录成功 → 进入 #/app/out-records（替代原 #/app/out）；已登录直接进入。

### 1.4 出库记录「状态」列功能设计（G4，核心）

#### 1.4.1 数据存储方案（重点评估）

**结论：允许谨慎新增可选字段 `status`（推荐）。**

- 新增可选字段：`status?: "pending" | "submitted"`，仅出库记录（type 非 "in"）使用；入库记录不写该字段。
- **兼容性论证**：
  - 该字段为可选，缺失时视图层按「已提单」处理，**不破坏任何现有数据**（现有 4 条出库记录无 status → 显示已提单）。
  - 记录 JSON 整体经 Contents API 原样读写，新增字段不改变 `{id,time,picker?,dept?,purpose,items,photos,_ts,affectsStock,type?}` 冻结 schema 的既有字段；`mergeAndSort` 按 id 覆盖合并，status 随记录整体携带，无需额外合并逻辑。
  - 旧设备（legacy.html）读到含 status 的记录仍可正常渲染（多余字段被忽略）。
- **默认值逻辑**：
  - 新出库记录（落地页提交）→ 创建时写入 `status: "pending"`（未提单）。
  - 已有记录 / status 缺失或未知值 → 视图层显示「已提单」（满足「已存在的 4 条出库记录直接显示已提单」）。
  - 编辑已有出库记录（落地页 pendingEditId 编辑流程）→ **不覆盖 status**；`Records.update` 用 Object.assign 合并 patch，payload 不携带 status 即保留原值。
- **实现建议**：
  - `out.js` 新建出库记录时 payload 增加 `status: "pending"`（编辑时不加）。
  - 新增读取函数（如 `Records.getStatus(rec)`）：`rec.type === "in" ? null : (rec.status === "pending" ? "pending" : "submitted")`，统一视图层判断。
  - 入库记录模块不显示状态列。

#### 1.4.2 表格新增「状态」列

- 位置：出库记录表（out-records）表头在「领取人」「部门」之间插入「状态」。
- 入库记录表不变（无状态列）。
- 样式：
  - 未提单：**红色点亮**（红点/红底白字圆角徽标），如 `● 未提单`，红 `#f04438` / 浅红底 `#fff0f0`。
  - 已提单：**绿色点亮**（绿点/绿底白字圆角徽标），如 `● 已提单`，绿 `#10b981` / 浅绿底 `#e8f7ee`。
  - 建议「圆点 + 文字」胶囊样式，保证移动端可读。

#### 1.4.3 手动更新交互

**推荐方案：点击状态徽标 → 弹确认框 → 切换。**
- 点击「未提单」徽标 → confirmDialog「标记为已提单？」→ 确认后 `status = "submitted"`，本地保存 + 立即推送云端（`Cloud.push(rec)` 或 `pushAllLocal`）。
- 点击「已提单」徽标 → confirmDialog「标记为未提单？」→ 确认后 `status = "pending"`，同样保存 + 同步。
- 备选方案（若希望更轻）：状态徽标旁放小按钮「标为已提单」/「标为未提单」；不推荐下拉菜单（移动端不便）。
- 操作成功后 toast 提示并刷新列表；`Cloud` 无令牌时仅存本地（沿用现有模式）。

#### 1.4.4 关联模块影响

- CSV 导出：出库记录导出增加「状态」列（P1，建议本期做，保证导出与页面一致）。
- 详情弹窗：出库详情增加「状态」行（P1）。
- 仪表盘「最近出库」：可加状态小标（P2 可选，不强求）。

### 1.5 多彩配色方案（G5，全局视觉）

**原则**：多彩 ≠ 廉价花哨；采用「低饱和高明度渐变的现代 SaaS 风格」，彩色只做点缀与层次，正文与数据区保持高可读性。

| 令牌/角色 | 取值 | 用途 |
|---|---|---|
| `--primary` | `#6366F1`（靛蓝） | 主色/链接/选中 |
| `--primary-2` | `#8B5CF6`（紫罗兰） | 主渐变终点 |
| `--grad-main` | `linear-gradient(135deg,#6366F1,#8B5CF6)` | 主按钮/主强调渐变 |
| `--grad-sunset` | `linear-gradient(135deg,#F97316,#F59E0B)` | 橙色系强调（今日出库等） |
| `--grad-ocean` | `linear-gradient(135deg,#14B8A6,#38BDF8)` | 青色系强调（今日入库等） |
| `--grad-pink` | `linear-gradient(135deg,#EC4899,#F472B6)` | 玫红系强调（低库存预警等） |
| `--grad-rainbow` | `linear-gradient(90deg,#F97316,#F59E0B,#10B981,#38BDF8,#6366F1,#A855F7,#EC4899)` | 顶栏彩条/装饰渐变 |
| `--bg` | `linear-gradient(160deg,#EEF2FF,#FDF2F8,#F0FDF4)` | 页面背景（柔和多彩） |
| `--green` | `#10B981` | 成功/已提单 |
| `--danger` | `#F04438` | 危险/未提单/低库存 |
| `--text` | `#1E293B` | 正文 |
| `--muted` | `#64748B` | 次要文字 |
| `--radius` | `12px`（卡片/按钮/弹窗） | 圆角提升 |
| `--shadow` | `0 8px 24px rgba(99,102,241,.10)` | 卡片柔和阴影 |

**应用范围**：
- 侧栏：深色 → 可保留深色（对比强）或改深靛蓝渐变；激活项使用主渐变背景 + 白字（多彩感更明显）。
- 仪表盘/报表统计卡：四张统计卡各配一种渐变（靛蓝/橙/青/玫红），图标底色渐变。
- 表格：斑马纹/表头浅色渐变；库存状态徽标（正常=绿、低库存=红）。
- 按钮体系：主按钮渐变、幽灵按钮描边主色、危险按钮保留红。
- 徽标体系：`.tag` 支持 `ok-tag`（绿）/`danger-tag`（红）/`pending-tag`（橙，可选）。
- 趋势图/排行条：出库=靛蓝、入库=翠绿，或改用多彩渐变条。

### 1.6 云端令牌设置入口设计（G6）

**现状**：sync.js（云端同步模块）已存在但**未挂入任何菜单**（NAV_ITEMS / VIEW_MAP / KNOWN_MODULES 均无 sync）；`Config.GH.token` 由 workflow 注入的 `window.__GH_TOKEN__` 优先，localStorage `gh_token` 兜底。

**入口方案（保持菜单 6 项不动）**：
- 在 Windows 桌面壳顶栏（win-topbar）右侧新增「云端同步」图标按钮（云朵/齿轮图标 + 可选文字），点击 → `Views.app.mount("sync")` 挂载云端同步模块。
- 同步为 VIEW_MAP 增加 `sync: "sync"`；可选：router KNOWN_MODULES 增加 `sync` 以便 `#/app/sync` 直达（推荐，便于分享/书签）。
- 侧栏底部保留「导入数据」；如实现简单，也可在侧栏底部加「云端同步」小按钮（二选一，建议顶栏按钮，更显眼）。

**同步模块内「云端令牌」设置 UI**：
- 状态展示行：当前令牌状态（部署注入 / 本地设置 / 未配置）+ 令牌掩码展示（如 `ghp_****abcd`，只显示末 4 位，避免明文泄露）。
- 设置区：密码类型输入框（placeholder「粘贴 GitHub 令牌」）+ 「保存令牌」按钮 → `localStorage.setItem("gh_token", value)` 并同步更新 `Config.GH.token`；toast「令牌已保存」。
- 清除区：「清除本地令牌」按钮 → `localStorage.removeItem("gh_token")`，恢复为仅依赖注入令牌（若存在）或未配置。
- 说明文案：部署版已自动注入令牌，通常无需手动设置；手动设置用于本地调试/未注入场景。
- **安全注意（PRD 要求）**：文档/实现中不硬编码令牌明文，令牌值由实现阶段从 `window.__GH_TOKEN__` / Secret 环境读取；PRD 内统一以 `GH_TOKEN_SECRET` 占位。输入框 type=password，保存后掩码展示。
